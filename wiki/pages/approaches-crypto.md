# Cryptographic alternatives to trusted hardware

FHE, MPC-as-mind, functional encryption, iO/witness encryption, timelock cryptography, hybrids. Question answered: can an agent be confidential and self-custodied without any TEE?

Raw verified findings from the horizon scan of 22 Nov 2026 (one stream per axis; every item carries a source the scanner fetched). Synthesis + maturity arbitration TODO in daily rotations; claim cells from the [approaches map](approaches.md).

- **FHE LLM inference cost at 7B scale: CryptoLab researchers (Stehle & Shin, NIST WPEC) reported one first-token forward pass of Llama2-7B homomorphically takes ~181.5 seconds on 8 GPUs with the HEaaN CKKS library, roughly 2^42 bit operations per token - plaintext would be well under a second. Best published end-to-end figure for a ~7B model; orders of magnitude off interactive latency.** (research | 2024-09-25) — <https://csrc.nist.gov/csrc/media/presentations/2024/wpec2024-2b3/images-media/wpec2024-2b3-slides-junbum-damien--CKKS-classify.pdf>
- **UC Berkeley EECS tech report implemented encrypted Llama-2 inference via Zama's Concrete-ML FHE server: a 5-token output from a 7-token input took 21,804-34,630 seconds (6-9.6 hours) and 137-283 GB of ciphertext transfer - full-token-level FHE LLM inference is orders of magnitude from practical on commodity hardware.** (research | 2024) — <https://www2.eecs.berkeley.edu/Pubs/TechRpts/2024/Archive/EECS-2024-225.pdf>
- **EncryptedLLM (De Castro, Escudero, Polychroniadou et al., ICML 2025): GPU-accelerated FHE benchmarks an encrypted GPT-2 forward pass at >200x faster than the CPU baseline, with activation-function approximation analysis - strongest published GPU-FHE LLM result, still only for a ~0.1B model.** (research | 2025) — <https://proceedings.mlr.press/v267/de-castro25a.html>
- **Zama Concrete ML supports FHE LLM inference (hybrid client/server) and encrypted LoRA fine-tuning: GPT-2 token generation ~11 s/token on GPU (~300 s on CPU); a Llama-1B LoRA fine-tuning pipeline fully under FHE runs at 64 tokens/s on a desktop GPU but takes ~28 hours on 50 GPUs for a small dataset - encrypted fine-tuning is closer to practical than encrypted inference.** (prototype | 2025-04-10) — <https://www.zama.org/post/concrete-ml-v1-9>
- **Encryption-Friendly LLM Architecture (Apple, arXiv:2410.02486) redesigns the transformer itself (FHE-aware attention/norms) to run under CKKS on 8x RTX 4090 with HEaaN - co-designing architectures for FHE is the main near-term lever for LLM-scale encrypted inference.** (research | 2024-10-03) — <https://arxiv.org/html/2410.02486v1>
- **Baseline the alternatives must beat: ETH SPCL measured confidential LLM inference (Llama3-8B, GPT-J, Falcon-7B, etc.) in CPU TEEs (SGX/TDX) and NVIDIA H100 confidential GPUs at only 0.1-13.1% overhead - TEEs run 7B-70B models at near-full speed today; that is the performance gap any pure-crypto substrate must close for a sovereign agent's mind.** (research | 2025-09-23) — <https://spcl.inf.ethz.ch/Publications/.pdf/IISWC25_confidential_llms.pdf>
- **DARPA DPRIVE (Duality/TREBUCHET, Galois, SRI, Intel teams; awarded March 2021) set the explicit goal of FHE computation within one order of magnitude of plaintext; the program is now marked complete by DARPA without a fielded 10x accelerator.** (prototype | 2021-03-08) — <https://www.darpa.mil/research/programs/data-protection-in-virtual-environments>
- **TREBUCHET (Duality/USC-ISI/NYU/CMU, DPRIVE) Phase 2 GOMACTech paper: modeled SerDes ASIC configuration meets DPRIVE benchmarks (logistic-regression training 89 ms, CNN inference ~200 ms) with ~3,146x speedup over single-thread CPU - performance-model estimates on a design point, not measured silicon at LLM scale.** (prototype | 2024) — <https://users.ece.cmu.edu/~franzf/papers/gomactech2024.pdf>
- **Intel Heracles (ISSCC 2026, IEEE Spectrum 2026-03-10): first large-scale FHE SoC - 197 mm2 Intel 3 nm, 8192-way SIMD, 48 GB HBM3 at 819 GB/s, 176 W liquid-cooled; up to ~5,000x FHE speedup vs a 24-core Xeon (ballot-query demo: 14 microseconds vs 15 ms). A demonstration, not a product; 5,000x still leaves a large residual gap for transformer-scale workloads.** (prototype | 2026-03-10) — <https://spectrum.ieee.org/fhe-intel>
- **Cornami Mx2 (EE Times, Raise 2025): 2048-core, 16 nm TSMC dataflow chip claims FHE-encrypted inference 1700x faster than an NVIDIA DGX-H100; a banking benchmark ran FHE-encrypted training in 3.8 s vs 3.7 s plaintext using four servers - closest claimed FHE-at-plaintext-speed, but CKKS software stack was pre-beta, ~25 demo units, vendor-reported claims.** (prototype | 2025-08-29) — <https://www.eetimes.com/cornami-targets-fhe-encrypted-ai-in-real-time/>
- **Optalysys: silicon-photonics accelerator performing FHE's Fourier/number-theoretic transforms optically; photonic chiplets taped out and driven from FPGAs in the cloud, current speedup ~100x with 10,000x targeted, fully integrated hybrid chips 3-4 years away (as of Sept 2024); partnered with Google's HEIR compiler (Oct 2024). Real tape-outs, unproven at system level.** (prototype | 2024-09-10) — <https://optalysys.com/resource/silicon-photonics-our-approach-to-acceleration/>
- **FHE hardware ecosystem breadth (vendor-by-vendor audit, reviewed 2026-11-09): Zama became FHE's first unicorn ($57M, Jun 2025); Niobium raised $23M+ (Dec 2025) for production-ready silicon pilots; FHETCH consortium (Optalysys, Niobium, Chain Reaction) formed Oct 2024; ISO/IEC 28033 FHE standardization underway; no vendor has shipped a named production deployment of FHE silicon.** (prototype | 2026-11-09) — <https://homomorphicprivacy.com/articles/fhe-market-and-vendors/>
- **5-year trajectory synthesis: software FHE gains have plateaued (Craig Gentry, CACM Jun 2025: further performance must come from hardware); credible 2026-2031 path is niche encrypted-classification/private-query workloads reaching ~10x-of-plaintext on custom silicon by ~2028-2030, while 7B-70B LLM token generation under FHE stays minutes-to-hours per token within 5 years - FHE for a sovereign agent's full mind is not a 5-year artifact; FHE for its state/memory at rest already is.** (research | 2025-06-04) — <https://cacm.acm.org/news/homomorphic-technologies-could-process-still-encrypted-data/>
- **MPC substrate for a distributed agent mind: MP-SPDZ (CCS 2020, actively maintained) implements 30+ protocols behind one interface - malicious-secure SPDZ computes a 100,000-element 64-bit inner product in 67 s LAN / 170 s WAN; guaranteed output/fairness is impossible with dishonest majority and malicious MPC is abort-only, a fundamental availability constraint for an agent whose state is secret-shared across untrusted nodes.** (prototype | 2020-11-09) — <https://github.com/data61/MP-SPDZ>
- **CrypTen (Meta, NeurIPS 2021): PyTorch-native secret-sharing MPC library supporting arithmetic via Beaver triples and polynomial approximations of nonlinearities - ML-shaped computation can be expressed as MPC without protocol expertise, but its honest-majority/trusted-dealer setup model differs from an adversarial distributed-mind setting.** (prototype | 2021-09-01) — <https://arxiv.org/html/2109.00984v2>
- **Scaling MPC-ML to many nodes (USENIX Security 2024): honest-majority semi-honest MPC performs oblivious inference of a 4-layer CNN with 63 parties in 0.1 s LAN / 4.6 s WAN, first fully implemented PPML protocol at that party count, 1.4x faster than Falcon even at 3 parties - MPC tolerates large, fault-tolerant committees, a precondition for a node swarm as an agent substrate.** (research | 2024-08) — <https://www.usenix.org/system/files/sec24summer-prepub-278-liu-fengrun.pdf>
- **SMASH (USENIX Security 2026): maliciously secure hybrid MPC framework targeting LLM inference (models up to Qwen3-0.6B), constant 2-round online design robust to WAN (only ~0.2-0.3 s LAN-to-WAN penalty up to 32 parties, vs MP-SPDZ A2B at 1,514 s / 34 GB at 32 parties) - state of the art for an LLM forward pass as MPC among mutually distrusting nodes, still sub-1B models.** (research | 2026) — <https://www.usenix.org/system/files/usenixsecurity26-lv.pdf>
- **MPC is production-grade for keys (not computation): Fireblocks' CGGMP threshold-ECDSA protocol signs in 3 rounds, 200-500 ms computation per party, 15-23 KB communication, never reconstructing the key; Fireblocks claims 10-15% of mainnet blockchain transactions. Existence proof that secret-shared state + distributed signing works at internet scale - a sovereign agent's wallet/identity layer is deployable today without hardware.** (production | 2026-01-27) — <https://csrc.nist.gov/csrc/media/presentations/2026/mpts2026-2a2/images-media/mpts2026-2a2-slides-fireblocks-3mi-ecdsa-nikos.pdf>
- **One-time programs without secure hardware: Eldridge, Goel, Green, Jain, Zinkus (eprint 2022/1257) realize Goldwasser et al.'s CRYPTO 2008 one-time programs using counter lockboxes - password-protected key storage with limited incorrect-guess counts already available in consumer devices/cloud platforms - a narrow path to execute-once, copy-resistant agent programs (still leaning on a stateful hardware feature).** (research | 2022-09-01) — <https://eprint.iacr.org/2022/1257>
- **Functional encryption niches: QUILT (eprint 2026/1033, AsiaCCS) constructs one-time noisy multi-client FE for quadratic functions without bilinear-map structure, with 4.8-6.8x speedups for private logistic-regression training - single-evaluation FE is usable for specific ML tasks; general FE remains tied to iO-grade machinery.** (research | 2026-05-24) — <https://eprint.iacr.org/2026/1033>
- **Concrete cost ceiling of FE/obfuscation: 5Gen-C (CCS 2017) obfuscated a 64-bit-key PRF (62k gates) in under 4 hours with ~1 hour evaluation - most complex function obfuscated to date at that time - even tiny circuits cost hours-per-operation with cryptographically sound obfuscation; not closed for agent-scale programs as of 2026.** (research | 2017-10-30) — <https://eprint.iacr.org/2017/826>
- **iO theory status: GGSW13 (eprint 2013/451) founded the field on multilinear maps whose assumptions later suffered cryptanalysis; Jain-Lin-Sahai (EUROCRYPT 2022) achieved iO from well-founded assumptions, and Ragavan-Vafa-Vaikuntanathan (eprint 2024/856) removed the NC0-PRG requirement using bilinear maps + LPN variants - iO now rests on plausible assumptions but every known construction is astronomically far from practical.** (theory | 2024-06-05) — <https://eprint.iacr.org/2024/856>
- **Post-quantum iO directions: Cini-Lai-Woo (CRYPTO 2025, eprint 2025/1129) build lattice-based iO from NTRU + a new Equivocal-LWE assumption; Agrawal-Kumari-Yamada (eprint 2024/1720) give pseudorandom MIFE/iO from evasive LWE - first nontrivial iO-flavored primitives from conjectured post-quantum assumptions, relevant to long-lived sovereign agents.** (theory | 2025-08-01) — <https://eprint.iacr.org/2025/1129>
- **Practical-iO efforts are paper-stage: Diamond iO (eprint 2025/236, Ethereum Foundation-affiliated) removes the FE-to-iO transformation bottleneck (claimed 2^118-fold improvement on that step) yet concedes PFFE decryption remains dominant; Ma-Dai-Shi (eprint 2025/307) get quasi-linear iO only given succinct equivalence proofs. Neither ships a runnable system beyond toy PRF circuits.** (theory | 2025-03-01) — <https://eprint.iacr.org/2025/236>
- **Signal that software iO is not practical in 2026: HardCODE (eprint 2025/1989) achieves the first practical demonstration of iO-class obfuscation by using a tamper-proof HSM to hold a key, i.e., trusted hardware - the best working iO still routes through hardware; pure-software iO has no practical niche at any circuit size today.** (research | 2025-10-24) — <https://eprint.iacr.org/2025/1989>
- **iO's clearest agent-relevant target: Scalable Private World Computer via Root iO (eprint 2025/2139, Ethereum Foundation position paper) sketches a single application-agnostic obfuscated root circuit + FHE + SNARK giving Ethereum-scale confidential smart contracts with no committee trust - exactly the sovereign shared mind primitive - and lists the missing pieces (verifiable FHE, homomorphic PRF/SNARK evaluation over key-homomorphic encodings) as unsolved.** (theory | 2025-11-01) — <https://eprint.iacr.org/2025/2139>
- **Witness encryption: general-purpose WE (GGSW13) remains impractical per Garg's NIST retrospective (Jan 2025); practical niches are special-purpose WE - hash proof systems, laconic OT, threshold/mempool-privacy encryption - so encrypt-to-a-condition works today only where the condition has algebraic structure, not for arbitrary NP statements.** (theory | 2025-01-16) — <https://csrc.nist.gov/csrc/media/presentations/2025/stppa7-witness-encryption/images-media/stppa7-witness-encryption.pdf>
- **Witness encryption for Bitcoin key release - Bitcoin PIPEs v2 ([alloc] init): lock a Bitcoin signing key under an NP statement so it is decryptable only with a valid witness (e.g., a SNARK proof), enabling covenant-like spending with no soft fork. Concrete AADP-based instantiation requires ~338 TB ciphertexts for SNARK-verification predicates with heuristic (unproven) security - a research program, not a deployable primitive.** (theory | 2026) — <https://www.allocinit.xyz/uploads/pipesv2.pdf>
- **Committee-flavored witness encryption: Cassiopeia (eprint 2023/635) makes on-chain WE practical by replacing cryptographic hardness with a partially trusted committee holding shares - the recurring pattern: whenever general-NP encryption-to-a-condition becomes practical, trust moved into a threshold set rather than vanishing.** (research | 2023-05-05) — <https://eprint.iacr.org/2023/635>
- **VRFs are standardized and production: RFC 9381 (IRTF CFRG, Aug 2023) specifies ECVRF/RSAVRF constructions; drand's threshold-BLS beacon doubles as a VRF for the League of Entropy mainnet (production since 2020, 100% uptime, 3 s rounds, used by Filecoin and Cloudflare). Unbiased, publicly-verifiable randomness for an agent's key generation/lotteries needs no hardware.** (production | 2023-08-01) — <https://www.rfc-editor.org/rfc/rfc9381.pdf>
- **Timelock encryption for escrow/delayed release is production without hardware: drand tlock (eprint 2023/189) encrypts to a future beacon round using threshold IBE; tlock CLIs, tlock-js, tlock-rs and timevault.drand.love are live, audited by Kudelski Security (May 2023, issues fixed). Caveats: trust reduces to a t-of-n committee (quantum-vulnerable, network-shutdown risk) - delayed key escrow without hardware exists, but no-trust-at-all does not.** (production | 2023-05-23) — <https://kudelskisecurity.com/research/audit-of-drand-timelock-encryption>
- **Hardware-free timed release beyond committees: the Rivest-Shamir-Wagner RSA time-lock puzzle remains the only widely deployed trust-free primitive; recent work adds verifiability (verifiable TLPs, eprint 2025/225, proving NP properties of puzzle solutions) and scalability (ED-TLP delegated puzzles, AsiaCCS 2025). Pure drand-independent time-based escrow stays research-grade: costs scale linearly with delay and verification is expensive.** (research | 2025-03-01) — <https://eprint.iacr.org/2025/225>
- **SoK: Delay-Based Cryptography (IEEE CSF 2023) systematizes time-lock puzzles, timed commitments/signatures, VDFs and delay encryption: timed commitments (Boneh-Naor lineage) enable forced-open key escrow/contract signing but scale poorly with party count, and delay-encryption constructions remain impractical (one requires 12 TiB storage with setup time growing with the delay) - the delay-based toolbox is real but its no-trust variants are the weakest link.** (research | 2023) — <https://store.computer.org/csdl/proceedings-article/csf/2023/219200a426/1On91gWwHsI>
- **Hybrid design evidence (FHE for memory/linear layers + local compute): Zama Concrete ML's HybridFHEModel splits LLM inference - client performs nonlinear layers (attention, activations) locally, server runs only linear layers on encrypted activations; encrypted transfer ~18 MB/token for Llama-1B, ~2.2 MB/token for GPT-2. The FHE-for-data-at-rest/transfer pattern is the only FHE-LLM mode that runs today, and generalizes to a sovereign agent keeping weights encrypted on hostile storage while thinking locally.** (prototype | 2025-04-10) — <https://docs.zama.org/concrete-ml/llms/inference>
- **HE+TEE hybrid designs reintroduce hardware: THEF (IEEE TrustCom 2024) uses homomorphic encryption for confidentiality plus a TEE to avoid HE's polynomial-approximation cost of nonlinearities, cutting end-to-end communication 80% - informative for the design space, but not an alternative to trusted hardware, only a cheaper use of it.** (research | 2024) — <https://www.computer.org/csdl/proceedings-article/trustcom/2024/062000b693/25DHWSBe9nG>
- **MPC tooling benchmark maturity: a 2026 ScienceDirect study benchmarks 65 real-world MPC applications across four frameworks (HPMPC, MPyC, MP-SPDZ, MOTION) under bandwidth/latency/loss conditions - MPC for ML-shaped workloads is measurable engineering, with WAN latency (not CPU) the dominant cost, the binding constraint for a secret-shared agent mind spread across nodes.** (research | 2026) — <https://www.sciencedirect.com/science/article/pii/S2214212626002012>

## 2026 wave: FHE reaches 8B scale (rotation 23 Nov 2026)

Findings from a 23 Nov sweep; each number was read from the linked paper's own text.

- **Perseus (Zirilli, Marincione, Kornaropoulos, Ateniese, Rodolà; arXiv 2611.04488 + eprint 2026/2735, Nov 2026): state-of-the-art encrypted single-token decode of Llama-3-8B at 7.8 s/token at 512-token context on a single RTX Pro 6000 GPU — its Table 1 ladder: AR-HE 1569 s/tok (H100), ROSETTA 311 s/tok (A100), Cachemir 97 s/tok (A100), Sylph 31 s/tok (RTX Pro 6000), Perseus 7.8 s/tok. Open Python library on a Rust/CUDA CKKS 32-bit backend (BUSL 1.1), with a public single-token-decode speedrun leaderboard intended to compound progress.** (prototype | 2026-11-03) — <https://arxiv.org/abs/2611.04488>
- **Sylph (arXiv 2601.18511, Jan 2026): FHE Llama-3-8B prefill of a 128-token private prompt in 20 s on 8× RTX Pro 6000 (26 s on 4× B200); first heterogeneous public/private prompt design — thousands of plaintext context tokens ride along free while only the sensitive tail is encrypted.** That public-context/private-state split matches an agent's actual workload (public docs + private state) far better than fully-encrypted prompts. (research | 2026-01) — <https://arxiv.org/html/2601.18511>
- **Cerium (CMU CAOS, arXiv 2512.11269, open-source): first GPU CKKS bootstrapping under 10 ms (7.5 ms) and Llama-3-8B prefill in 43 s; the compiler/runtime gets GPUs within 4.4× of the CraterLake FHE ASIC — commodity GPUs are closing on dedicated silicon.** (prototype | 2025-12) — <https://arxiv.org/html/2512.11269v2>
- **Odin (arXiv 2609.12378, Sep 2026): first open-source end-to-end GPU CKKS Llama-3-8B — 366.4 s for a 128-token input on one H100 (58.9 GiB device memory), 4.51× over the THOR baseline on identical settings; packing co-design (feature-major cross-layer layout) is where the win comes from.** (research | 2026-09-11) — <https://arxiv.org/abs/2609.12378v3>
- **ATLAS (arXiv 2607.23478): automated search for polynomial approximations of transformer nonlinearities — ~35% multiplicative-depth and latency reduction on Llama-3-8B with negligible accuracy loss, search completing in under one hour; removes the expert-manual bottleneck in every FHE-LLM pipeline above.** (research | 2026-08-27) — <https://arxiv.org/html/2607.23478v2>
- **Bifrost (arXiv 2606.17421): hybrid TEE–FHE serving — linear layers on encrypted accelerator CKKS, nonlinear/KV/refresh inside an attested CPU TEE; projected 9.91× latency reduction on Llama-3-8B vs FHE-only. Recorded here as the design-space boundary: it is a cheaper use of trusted hardware, not an alternative to it (defender note in the TEE cell).** (research | 2026-06) — <https://arxiv.org/html/2606.17421>

### Answered P1b cell: can an FHE+local-compute hybrid reach interactive latency for an 8B agent?

- **Interactive** = ~1 s/token (chat-grade). **Best full-FHE 8B decode: 7.8 s/token on one datacenter GPU** (Perseus, Nov 2026). Two-year software-only trajectory: 181.5 s/tok (Llama-2-7B, Sep 2024) → 31 s/tok (Sylph) → 7.8 s/tok — roughly 20× per two years from packing/bootstrapping/approximation work alone. Verdict: **not interactive yet, but ~8× away, not 100× away** — and multi-GPU decode scaling plus the speedrun leaderboard make <2 s/token a plausible 2027 milestone. The falsifiable trigger: Perseus's public speedrun crossing ~1 s/token on one GPU marks an encrypted-mind agent as latency-viable for interactive use.
- **The hybrid (local nonlinear + FHE linear) mode works today** (Concrete ML HybridFHEModel at 1B, ~18 MB encrypted transfer/token) and 2026 packing advances shrink its dominant cost (ciphertext transfer + weight encoding), but **no published 8B hybrid number exists** — that remains the measurement gap. The pragmatic near-term configuration for a sovereign agent is Sylph-shaped: public context in plaintext, only private state encrypted.
- **What would have to be true**: (a) decode <1 s/token via speedrun compounding or CraterLake-class ASIC availability (Cerium shows GPUs at 4.4× of ASIC); (b) a published 8B hybrid-FHE latency measurement; (c) weights-at-rest under FHE is already deployable — the open frontier is the thinking loop, not storage.
